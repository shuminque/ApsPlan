# 当前排产逻辑说明（基于 autoPlanBrowse 页面）

本文仅基于前端页面 `src/main/resources/templates/014/autoPlanBrowse.html` 的现有实现，说明“自动排产”在页面侧的完整交互与数据流。

## 1. 页面入口与默认时间范围

页面加载后会自动初始化隐藏的日期范围：

- `planStart`：当月 1 号；
- `planEnd`：下月 1 号。

虽然日期控件在页面上被隐藏，但后续所有预览请求都依赖这个时间范围。

## 2. 整体交互流程

用户点击“自动排产”后，流程分为 4 个阶段：

1. **浏览数据请求**：调用 `/api/shift/plan/preview` 拉取订单汇总（首轮预览）；
2. **设置开始时间**：弹窗中逐条订单汇总填写“开始时间”；
3. **结果预览**：带 `orderStartTimes` 再次调用 `/api/shift/plan/preview` 获取正式排产结果；
4. **写入排产**：在结果弹窗确认后，调用 `/api/shift/plan/commit` 提交。

若触发“插单”场景，会在第 3、4 阶段间插入“推荐产线选择”确认步骤。

---

## 3. 阶段一：浏览数据请求（preview 第一次）

方法：`requestAutoPlanBrowseData()`。

### 3.1 请求条件

- 会读取当前 `planStart/planEnd`；
- 若任一为空，直接提示“请先选择浏览开始/结束日期”，不发请求。

### 3.2 请求体

```json
{
  "start": "yyyy-MM-dd",
  "end": "yyyy-MM-dd"
}
```

### 3.3 返回数据在前端的用途

- 结果存入 `planBrowseData`；
- 从 `orders` 提取订单组键（`customer||outerInnerRing||model`）；
- 构建/刷新 `planOrderStartMap`：
  - 已有键沿用用户上次填写的开始时间；
  - 新键默认使用 `range.start`。

这一步相当于“浏览 + 预填开始日期缓存”。

## 4. 阶段二：订单分解弹窗与开始时间收集

方法：`openPlanBrowseDialog(data)`。

### 4.1 展示内容

弹窗标题：**自动排产 - 浏览分解**。

列表按 `orders` 展示字段：

- 客户、内外圈、型号、最早交期；
- 在库数量、订单需求数、安全库存数、计划排产数；
- 每行一个可编辑 `开始时间`（date input）。

其中每行会带上 `orderIds`（JSON 字符串），用于把“组级开始时间”映射回“订单级开始时间”。

### 4.2 点击“排产”后的校验与映射

- 遍历所有订单汇总行；
- 若任一行开始日期为空，阻断并提示“请为每条订单汇总填写开始时间”；
- 将开始日期写回 `planOrderStartMap`；
- 解析每行 `orderIds`，组装 `orderStartTimes`：
  - key = `orderId`（字符串化）；
  - value = 对应开始日期。

然后进入下一阶段正式预览。

## 5. 阶段三：结果预览（preview 第二次）

方法：`requestAutoPlanPreviewByOrderStart(orderStartTimes)`。

### 5.1 请求体

```json
{
  "start": "fallbackStart",
  "end": "planEnd",
  "orderStartTimes": {
    "订单ID": "yyyy-MM-dd"
  }
}
```

`fallbackStart` 规则：

- 优先取 `orderStartTimes` 中最早日期；
- 若没有则回退到当前 `planStart`。

### 5.2 返回数据处理

- 保存到 `previewPlanData`；
- 重置插单选择状态：
  - `selectedInsertLineIdsForCommit = []`；
  - `insertSelectionConfirmedForPreview = false`。

### 5.3 是否触发插单

通过 `data.autoInsertTriggered` 判断。

- **未触发**：直接打开结果预览弹窗；
- **已触发**：先弹“插单推荐产线”确认，确认后再打开结果预览。

## 6. 阶段四：结果预览弹窗与写入排产

方法：`openPlanPreviewDialog(data)`。

### 6.1 展示内容

弹窗标题：**自动排产结果预览**。

包含两张表：

1. **待排产订单汇总**：与阶段二类似（但无开始日期编辑）；
2. **排产结果**（`events`）：
   - 产线、客户、内外圈、型号；
   - 排产时间范围（`start~end`，仅展示日期部分）；
   - 天数、日产量、日均工时、小时产能、总产量。

其中：

- `dailyOutput`、`avgDailyWorkHours`、`capacityPerHour` 使用两位小数格式；
- 若事件包含 `metricDiagnosticTag` 且不为 `OK`，会附加在日产量后用于提示。

### 6.2 点击“写入排产”时的关卡

先执行 `handleCommitWithInsertSuggestion()`：

- 若当前预览触发了插单：
  - 必须已经确认插单产线，且已选产线数 `>= requiredInsertLineCount`；
  - 否则提示并强制进入“插单推荐产线”选择弹窗；
- 若未触发插单：清空插单相关状态，直接继续。

通过后会再弹一次确认框“确认将当前排产结果写入班次排班吗？”，确认后执行提交。

## 7. 插单推荐产线逻辑（页面侧）

核心方法：`openAutoInsertTriggerDialog()` + `openInsertLineRecommendationDialog()`。

### 7.1 触发后展示的信息

来自预览返回体：

- `requiredInsertQuantity`：插单缺口数量；
- `requiredInsertLineCount`：建议最少插单线数量；
- `insertDeadline`：对应交期；
- `insertSuggestion.candidateLines`：候选产线列表。

### 7.2 候选产线默认勾选规则

- `defaultSelectedIndex = requiredInsertLineCount`；
- 即默认勾选候选列表前 N 条（N 为最少需求线数）。

### 7.3 提交前硬性校验

用户在弹窗点“确定”时：

- 统计勾选的 `lineId`；
- 若勾选数 `< requiredInsertLineCount`，阻断并提示；
- 通过后写入：
  - `selectedInsertLineIdsForCommit`；
  - `insertSelectionConfirmedForPreview = true`。

### 7.4 风险标签说明（纯展示）

页面内置风险标签字典：

- `LOW`
- `LINE_STOPPED`
- `RUNTIME_UNKNOWN`
- `MODEL_UNKNOWN`
- `NO_CAPACITY`

当前页面仅负责展示说明与候选信息，不在前端做风险评分计算。

## 8. 最终提交（commit）

方法：`commitAutoPlan()`。

### 8.1 前置校验

- 若 `previewPlanData.events` 为空，提示“当前没有可写入的预览数据”，不请求。

### 8.2 请求体

提交地址：`POST /api/shift/plan/commit`

```json
{
  "selectedEvents": ["来自 preview 的 events"],
  "selectedInsertLineIds": ["lineId1", "lineId2"]
}
```

其中 `selectedInsertLineIds`：

- 插单场景下为用户确认结果；
- 非插单场景为空数组。

### 8.3 返回处理

- 返回值转数字 `inserted`；
- `inserted > 0`：提示“自动排产已写入班次排班”，并清空部分状态；
- `inserted == 0`：提示“未写入任何排产明细，请检查订单匹配条件或预览数据”；
- 异常：优先解析后端 JSON `message`，否则显示原始错误文本。

## 9. 当前页面逻辑特征总结

1. **两次 preview 请求**：先浏览订单，再带订单级开始时间做正式预览。
2. **按订单组录入开始时间，但按订单 ID 下发**：前端负责从“组视图”映射到“订单级参数”。
3. **插单是强制确认关卡**：触发后必须完成推荐产线选择，才允许写入。
4. **commit 提交的是预览事件集合**：页面不做二次拆解，直接提交预览结果。
5. **日期控件默认隐藏**：当前时间窗口主要靠页面初始化默认值驱动。

## 10. 关键前端状态变量（便于联调）

- `planBrowseData`：第一次 preview 的浏览数据；
- `planOrderStartMap`：订单组键 -> 开始日期；
- `previewPlanData`：第二次 preview 的结果数据；
- `selectedInsertLineIdsForCommit`：提交时选择的插单产线；
- `insertSelectionConfirmedForPreview`：是否已完成插单确认。
